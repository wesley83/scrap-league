## Reproduction and ownership

Use the pinned Bun lockfile: `bun install --frozen-lockfile`, `node tools/build.mjs`, then `node --test tests/*.test.mjs`. The build reads authoritative `content/`; it never runs the destructive authoring utilities. `node tools/release-gate.mjs local` refuses missing or non-passing acceptance, even when all unit tests pass. `tools/review-server.mjs` hosts explicit local browser review controls and records their release, user agent, viewport and method.

`app/` contains the runtime, shared model/compiler and editor. `tools/` contains build, review, deployment and rollback tooling. `audit/2026-10-16-remediation.md` is the append-only work record. Provider fixtures use unique owned paths and are cleaned up conditionally. Credentials and private baselines remain outside Git. Existing hosted releases and player documents are preserved.

## Mobile graphics repair — October 16, 2026

The user reported a white 3D surface with Chromium's broken-canvas marker on a Pixel 11 Pro running Edge. The exact device trigger and cached release are unknown. The game now defaults coarse-pointer devices to safer graphics (no multisample antialiasing or dynamic shadows, DPR capped at one, one-million-pixel allocation budget). Standard graphics also has a two-million-pixel allocation ceiling, and both profiles respect a conservative hardware dimension limit. A lost or empty drawing buffer is checked independently before simulation; shader/allocation failures enter the same stopped-race recovery path.

Settings and a graphics-failure pause provide **Repair graphics**. It disposes the failed renderer, replaces the canvas, rebuilds the scene with safer graphics, retains the current race/clock and requires explicit Resume. A failed repair stays paused and can be retried. Saved progress and editor drafts are unaffected. Mobile preference migration keeps existing controls and adopts safer graphics when the old preferences have no graphics-profile choice.

`audit/mobile-graphics-tests-final.txt` records the final automated suite. `tools/mobile-review.js` provides exact-release local browser fixtures for a suppressed loss event, failed renderer creation, fresh-canvas recovery, ordinary restoration, portrait/landscape and both rendering profiles. Browser receipts record their exact tested release and injected-fault scope. This is not device-side confirmation of the Pixel/Edge trigger. The earlier twenty-minute timing receipt remains historical evidence for its named renderer version; it is not a new soak of this repair.
